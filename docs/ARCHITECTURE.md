# Архитектура проекта

Подробное описание архитектуры сервиса сокращения ссылок.

## Обзор

Проект построен по принципам **Чистой Архитектуры** (Clean Architecture) и **Domain-Driven Design**. Код разделён на четыре основных слоя, каждый из которых имеет чёткие границы ответственности.

## Ключевые компоненты

### Domain Layer (Слой домена)

Содержит бизнес-логику, не зависящую от инфраструктуры.

- **Сущности**: `Link`, `User`, `Role`, `Permission` — неизменяемые данные с поведением
- **Объекты-значения**: `OriginalUrl`, `ShortCode`, `UrlHash`, `OwnerID` — валидированные параметры
- **Интерфейсы репозиториев**: `LinkRepository`, `UserRepository` — абстракции хранения
- **Политики**: `HashCalculator`, `CodeGenerator` — алгоритмы, передаваемые как зависимости

### Application Layer (Слой приложения)

Оркестрирует выполнение бизнес-операций.

- **Use case'ы**: каждый реализует один сценарий использования, наследует `BaseUseCase`
- **Фасады**: `LinkService`, `AdminService` — упрощают интерфейс для веб-слоя
- **DTO**: `ShortLinkResponse`, `BatchCreateResponse`, `UserActivityResponse` — данные для передачи
- **Порты**: абстракции инфраструктуры (`LinkCache`, `RedirectCache`, `StatsCache`, `Logger`, `UnitOfWork`, `HealthCheck`)

### Infrastructure Layer (Слой инфраструктуры)

Реализует порты и обеспечивает техническую поддержку.

- **Repository**: `SQLAlchemyLinkRepository` — преобразование domain ↔ ORM
- **Unit of Work**: `SQLAlchemyUnitOfWork` — управление транзакциями через контекстные менеджеры
- **Кэш**: `RedisLinkCache`, `InMemoryLinkCache`, `NullCache` — двухуровневое кэширование
- **Rate Limiter**: `RedisRateLimiter`, `MemoryRateLimiter` — sliding window алгоритм
- **Авторизация**: `JWTAuthService`, `RBACAuthorizationService` — JWT + RBAC
- **DI Container**: `Container` — ленивое создание и связывание компонентов через component-based архитектуру

### Web Layer (Веб-слой)

Обрабатывает HTTP-запросы и возвращает ответы.

- **Контроллеры**: `ApiController`, `DashboardController`, `AuthController`, `AdminApiController`
- **Middleware**: `AuthenticationMiddleware`, `ErrorHandlerMiddleware`, `RateLimitMiddleware`, `RequestLoggingMiddleware`
- **Декораторы**: `@login_required`, `@require_permission`
- **Схемы**: Pydantic модели для валидации входящих данных

## Безопасность

### Аутентификация

- JWT токены (access + refresh) через `PyJWT`
- Cookie-based авторизация для браузеров (HttpOnly, SameSite=Strict)
- `COOKIE_SECURE=true` по умолчанию в production
- CORS настроен для поддержки cookie (`supports_credentials=True`)

### Авторизация (RBAC)

Четыре роли с иерархией разрешений:

```
┌───────┐     ┌───────┐     ┌──────────┐     ┌───────┐
│ guest │────>│ user  │────>│ analyst  │────>│ admin │
└───────┘     └───────┘     └──────────┘     └───────┘
  регистрация   назначение     назначение
```

| Роль | Описание | Ключевые разрешения |
|------|----------|---------------------|
| guest | Неавторизованный посетитель | `stats:view_basic` |
| user | Зарегистрированный пользователь | `link:create`, `link:view_own`, `link:delete_own` |
| analyst | Аналитик | `stats:view_full`, `link:view_own` |
| admin | Администратор | `admin:all` (все разрешения) |

### Rate Limiting

- Гостевые ссылки: `GUEST_LINK_LIMIT` за `GUEST_LINK_WINDOW_DAYS`
- Auth эндпоинты: защита от brute-force
  - Login: 5 попыток / минуту по IP
  - Register: 3 регистрации / час по IP
  - Refresh: 10 попыток / минуту
  - Logout: 20 попыток / минуту
- API-эндпоинты: настраиваемые лимиты через `RATE_LIMITS` в конфигурации

## Кэширование

Двухуровневая система:

```
┌──────────────────────────────────────────────────────────────────┐
│                         КЭШИРОВАНИЕ                              │
│                                                                  │
│  ┌─────────────────────┐      ┌─────────────────────┐           │
│  │  L1 RedirectCache   │      │  L2 LinkCache       │           │
│  │  short_code →       │      │  short_code →       │           │
│  │  original_url       │      │  Link object        │           │
│  │  TTL: настраивается │      │  TTL: настраивается │           │
│  └──────────┬──────────┘      └──────────┬──────────┘           │
│             │                            │                       │
│  ┌──────────┴────────────────────────────┴──────────┐           │
│  │                                                  │           │
│  │  Запрос редиректа ──> L1 ──> попадание ──> быстрый редирект │
│  │                   │                                │           │
│  │                   └──> промах ──> L2 ──> попадание ──> ответ │
│  │                                  │                           │
│  │                                  └──> промах ──> PostgreSQL  │
│  │                                        │                     │
│  │                                        └──> обновить L2     │
│  │                                              └──> обновить L1│
│  └──────────────────────────────────────────────────────────────┘
│                                                                  │
│  Удаление: Cache.delete(short_code) очищает оба уровня кэша     │
└──────────────────────────────────────────────────────────────────┘
```

- **L1 (RedirectCache)**: `short_code → original_url` — быстрый редирект (TTL настраивается)
- **L2 (LinkCache)**: `short_code → Link object` — полные данные ссылки (TTL настраивается)

Инвалидация:
- **По TTL**: автоматическая
- **При удалении**: `Cache.delete(short_code)` очищает оба уровня кэша
- **Обработка ошибок**: ошибки инвалидации логируются, но не прерывают операцию

## Транзакционность

Паттерн Unit of Work:

```python
with self.uow_factory() as uow:
    link = uow.links.find_by_code(code)
    link.increment_clicks()
    uow.links.save(link)
    uow.commit()  # Явный коммит
# При выходе из контекста без коммита — автоматический rollback
```

## Логирование

Три уровня:

1. **Application Logger** — бизнес-события (создание, редирект, ошибки)
2. **Audit Logger** — аудит безопасности (создание, удаление, доступ)
3. **Failover** — автоматическое переключение при недоступности основного логгера

## Расширяемость

### Добавление нового use case

1. Создать `application/use_cases/<domain>/<name>.py`
2. Наследовать `BaseUseCase`, объявить зависимости как поля `@dataclass`
3. Реализовать метод `execute()`
4. Зарегистрировать в DI-контейнере (`infrastructure/di/components/use_cases/`)
5. Добавить геттер в `infrastructure/di/container.py`
6. Подключить к контроллеру или фасаду

### Добавление нового эндпоинта

1. Добавить метод в контроллер
2. При необходимости создать Pydantic-схему в `web/schemas/`
3. Добавить route в `_register_routes()`
4. При необходимости добавить декораторы авторизации

### Добавление новой роли

1. Определить разрешения в `domain/system_permissions.py`
2. Добавить роль в seed data
3. Выполнить `flask db load-base-roles`
