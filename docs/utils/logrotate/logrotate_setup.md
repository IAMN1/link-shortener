## Настройка logrotate для вашего проекта

После перехода на `WatchedFileHandler` ротация логов полностью передана внешней утилите **logrotate**. Теперь нужно создать конфигурационный файл для logrotate, который будет выполняться ежедневно и/или при достижении файлом определённого размера.

### 1. Понимание работы logrotate

Logrotate — стандартная утилита в Linux, которая автоматически ротирует, сжимает и удаляет старые логи. Она обычно запускается cron’ом раз в день (например, в `/etc/cron.daily/logrotate`). Конфигурационные файлы лежат в `/etc/logrotate.conf` и `/etc/logrotate.d/`.

Для Mac можно установить logrotate через Homebrew и настроить его запуск через launchd или просто запускать вручную для тестирования.

### 2. Создание конфигурационного файла

Создайте файл, например, `link_shortener` (без расширения) и поместите его в соответствующую директорию:

- **Linux (продакшен/разработка):** `/etc/logrotate.d/link_shortener`
- **Mac (локальная разработка):** можно положить в любое место, например `~/etc/logrotate.d/link_shortener`, и запускать logrotate с указанием этого файла.

**Содержимое файла:**

```bash
# Путь к файлу логов (измените на ваш)
/var/log/link_shortener/link_shortener.log {
    daily                     # ротировать каждый день
    maxsize 100M              # дополнительно ротировать, если файл превысит 100 МБ до ежедневной ротации
    rotate 30                 # хранить 30 последних ротированных файлов
    compress                  # сжимать старые файлы (gzip)
    delaycompress             # не сжимать только что ротированный файл (до следующей ротации)
    missingok                 # не выдавать ошибку, если файл отсутствует
    notifempty                # не ротировать пустой файл
    create 0644 appuser appgroup  # создать новый файл с указанными правами (замените appuser:appgroup)
    sharedscripts             # выполнять скрипт postrotate один раз для всех логов, если их несколько
    postrotate
        # Для WatchedFileHandler ничего делать не нужно – он сам переоткроет файл.
        # Если бы использовался другой хендлер, можно было бы отправить сигнал.
    endscript
}
```

**Важные параметры:**
- `daily` + `maxsize` обеспечивают ротацию по дате и по размеру.
- `create` задаёт права на новый файл. Убедитесь, что пользователь, от которого запущено приложение, имеет права на запись в этот файл. В Docker часто всё работает от root, тогда можно указать `create 0644 root root`. Лучше создать непривилегированного пользователя в контейнере.
- `postrotate` пуст – мы используем `WatchedFileHandler`, который автоматически переоткрывает файл при записи.

### 3. Применение конфигурации

#### На Linux (продакшен)
1. Поместите файл в `/etc/logrotate.d/`.
2. Проверьте синтаксис:
   ```bash
   sudo logrotate -d /etc/logrotate.d/link_shortener
   ```
   (ключ `-d` (debug) показывает, что будет сделано, но не выполняет ротацию)
3. Принудительно выполните ротацию для проверки:
   ```bash
   sudo logrotate -vf /etc/logrotate.d/link_shortener
   ```
   (`-v` – verbose, `-f` – force)
4. Убедитесь, что файл ротирован (появился `link_shortener.log.1` и т.д.).

#### На Mac (разработка)
1. Установите logrotate: `brew install logrotate`.
2. Создайте директорию для своих конфигов, например `mkdir -p ~/etc/logrotate.d`.
3. Положите туда файл с конфигурацией (путь к логам измените на локальный, например `/Users/username/projects/link_shortener/logs/link_shortener.log`).
4. Протестируйте:
   ```bash
   logrotate -d ~/etc/logrotate.d/link_shortener
   logrotate -vf ~/etc/logrotate.d/link_shortener
   ```
5. Чтобы logrotate запускался автоматически каждый день, можно добавить задание в cron (`crontab -e`):
   ```
   0 0 * * * /usr/local/bin/logrotate ~/etc/logrotate.d/link_shortener
   ```
   Или использовать launchd, но для разработки достаточно ручного запуска или просто ежедневного cron.

### 4. Настройка в Docker-окружении

У вас два основных подхода:

#### А. Ротация на хосте (рекомендуется)
- Логи пишутся в volume, смонтированный на хосте (например, `./logs:/var/log/link_shortener`).
- На хосте настраиваете logrotate так, чтобы он обрабатывал файлы внутри этого volume. Путь в конфиге указываете как абсолютный путь на хосте к этим файлам.
- Преимущество: не нужно усложнять образ Docker, logrotate работает стабильно.

**Пример для Docker Compose:**
```yaml
services:
  app:
    volumes:
      - ./logs:/var/log/link_shortener
```
Тогда в конфиге logrotate на хосте пишете:
```bash
/абсолютный/путь/к/проекту/logs/link_shortener.log {
    ...
}
```

#### Б. Ротация внутри контейнера
- В образе устанавливаете logrotate и настраиваете cron или запускаете logrotate как отдельный процесс.
- Это сложнее: нужно синхронизировать время, управлять несколькими процессами в контейнере (обычно используют супервизор, например s6, или запускают logrotate как отдельный контейнер).
- Менее предпочтительно, но возможно.

### 5. Проверка прав доступа

Самая частая проблема — новый файл, создаваемый logrotate, имеет неправильного владельца, и приложение не может в него писать. Решения:

- В параметре `create` укажите пользователя и группу, от которых работает приложение в контейнере. Если приложение работает от root (что не рекомендуется), укажите `root root`.
- Либо после ротации можно выполнить `chown` в `postrotate`, но лучше сразу создать файл с нужными правами.
- Убедитесь, что директория, в которой лежит лог, доступна для записи этому пользователю.

### 6. Пример для разработки на Mac с Docker

Допустим, у вас проект лежит в `~/projects/link_shortener`, и в docker-compose.yml вы смонтировали `./logs:/app/logs`. Тогда на Mac:

**Файл конфига** `~/etc/logrotate.d/link_shortener`:
```bash
/Users/username/projects/link_shortener/logs/link_shortener.log {
    daily
    maxsize 10M
    rotate 7
    compress
    delaycompress
    missingok
    notifempty
    create 0644
    sharedscripts
}
```

**Запуск теста:**
```bash
logrotate -vf ~/etc/logrotate.d/link_shortener
```

### 7. Интеграция с ELK в будущем

При использовании Filebeat или Fluentd для сбора логов в ELK они обычно следят за файлами и умеют работать с ротацией. Filebeat, например, отслеживает inode и автоматически продолжит читать новые файлы после ротации. Параметр `delaycompress` полезен, чтобы Filebeat успел дочитать старый файл до его сжатия.

### 8. Резюме

После выполнения этих шагов:
- Логи вашего приложения будут надёжно ротироваться по дате и размеру.
- Не возникнет проблем с несколькими воркерами благодаря `WatchedFileHandler`.
- Система готова к интеграции с ELK.
- Вы сможете легко управлять политикой хранения логов через logrotate.

Если возникнут сложности с правами или путями, всегда можно протестировать logrotate вручную с ключом `-d` и посмотреть ошибки.
